## C 工作台应如何组织

保留“工程工作空间 → 工作项 → 工程产物”的导航关系。原有五个页签继续作为稳定入口，将“开发流程”优化为默认执行工作台。运行记录仍承载完整历史，当前任务可就地打开相关运行详情。

```tree
SpecFlow 工作台
  全局导航 | 工作空间、工作项搜索、当前产物、工程设置
  紧凑工作项头部 | 名称、状态、待处理数量、更多操作
  视图入口 | 开发流程、需求输入、文档产物、代码与验证、运行记录
  当前工作区域
    流程分组 | 需求、设计、任务、实现、交付
    当前任务 | 本步骤摘要、主要动作、需要处理的问题
    工作主体 | 澄清问答、产物阅读、复核报告或运行详情
    上下文栏 | 输入版本、章程、模型、关联产物
  运行详情抽屉 | 原执行身份、停止、核对、恢复、原始输出
```

**桌面布局。** 使用“导航 + 工作主体 + 可折叠上下文”三栏。避免在流程页再叠加一条常驻步骤侧栏。流程目录放在主体顶部，采用分组折叠；默认展开当前分组和有问题的分组。

| 区域 | 建议尺寸与内容 |
| --- | --- |
| 全局导航 | 当前 236px，拟调整为 224px；紧凑模式 64px；长名称可查看完整内容 |
| 工作项头部 | 默认约 88px；显示名称与关键状态，摘要按需展开 |
| 当前任务区 | 一个主按钮；任务条在主内容滚动区顶部保持可见；相邻显示阻塞原因 |
| 工作主体 | 优先获得空间；长正文限制到约 64–78 字符的行宽 |
| 上下文栏 | 默认 320px，可在 280–400px 间调整；不足时收起 |
| 运行详情 | 主体内展开或右侧抽屉；同时最多一个主抽屉 |

**13 步只做视觉分组。** 执行顺序、输入依赖和门禁继续读取运行定义。

```flow LR
需求阶段 -> 设计阶段 -> 任务阶段 -> 实现阶段 -> 交付阶段
```

| 默认分组 | 现有步骤 |
| --- | --- |
| 需求 | 需求规格、需求澄清、规格复核 |
| 设计 | 工程设计、设计复核 |
| 任务 | 任务拆解、任务复核 |
| 实现 | 代码实现、测试与检查、代码复核 |
| 交付 | 收敛与对齐、收敛复核、接纳代码 |

分组映射用于当前默认流程。自定义流程保留定义顺序和全部节点，无法识别时使用未分组列表。旧运行按自己的定义展示，不补造澄清节点。

**选择与推荐分开。** 当前代码已在 `selectedNode` 非空时保留手动步骤选择，SSE 刷新不会清空它。没有手动选择时，派生逻辑才跟随活动步骤。切换工作项会清空位置，这是本轮要改善的部分。

显式区分“跟随当前任务”和“固定查看”两种模式。用户点击步骤、历史尝试或文档版本后进入固定查看；“回到当前任务”恢复跟随。跟随模式只更新任务推荐，不能覆盖已打开的历史版本、正文草稿或阅读位置。

**响应式规则。** 窗口宽度决定初始布局档位，主体内部使用容器查询压缩内容。自动收起按固定顺序执行：先收上下文，再将导航收成 64px。计算采用固定的外层尺寸，不能用收起后的余量立即反向展开。

| 窗口宽度 | 推荐呈现 |
| --- | --- |
| 不小于 1360px | 224px 导航、弹性主体、320px 上下文 |
| 1120–1359px | 初始导航 224px；若固定右栏后主体不足 560px，先收右栏，仍不足才收导航 |
| 901–1119px | 64px 导航、单一主体，上下文改为抽屉 |
| 651–900px | 复用完整导航抽屉；任务优先，上下文按需打开 |
| 不大于 650px | 单栏；编辑、预览和比较分别进入，不挤压成三栏 |

Electron 当前最小窗口为 1000×700。这个尺寸应默认使用紧凑导航和折叠右栏，确保主动作可见。390px 用于 Web 响应式验收。

仅在窗口跨入更宽档位或用户明确展开时恢复面板。展开前校验主体最小宽度；不能由容器宽度变化触发外层布局来回切换。面板拖宽也使用同一约束。

**700px 高度下的动作位置。** 工作项头部、页签之后放紧凑任务条，将主按钮固定在任务条内。流程分组和长正文在其下方滚动，阻塞详情可展开。任务条随主内容容器 sticky；不能把主按钮放在长检查器底部。200% 缩放时任务条允许换行，并为焦点与锚点预留滚动偏移。

**抽屉与焦点。** 窄窗口的运行和上下文共用一个详情容器，打开新详情时替换内容。导航临时覆盖时保留详情定位，关闭后恢复焦点与阅读位置。桌面常驻上下文为非模态面板，不锁定焦点；模态抽屉复用已有焦点管理，避免叠加焦点锁。

## D 当前动作和运行反馈如何工作

新增共享的 `StepStatusViewModel` 和 `NextAction` 展示模型。它们聚合现有事实，并由服务端决定动作是否可执行。展示模型不能修改门禁或替代服务端校验。

**四项事实独立展示。** 步骤列表、当前任务区和运行详情固定呈现下面四项，不合并成单枚状态徽章。窄屏可换成两行，但不得省略字段。

| 事实 | 读取依据 | 展示规则 |
| --- | --- | --- |
| 执行 | 节点 execution；详情另列本次 attempt 的 execution | 待执行、启动中、运行中、待交互、已结束、失败、停止、待核对 |
| 门禁 | 节点 gate | 待检查、通过、阻塞、过期；保持服务端原值 |
| 新鲜度 | 节点 freshness | 当前有效 / 上游已变更，并可展开所用版本 |
| 接纳 | 节点 acceptance、定义 requireAcceptance 和对应产物修订 | 区分待人工接纳、人工已接纳、系统已确认与无独立接纳动作；保留原值 |

复核和验证节点的 `acceptance=accepted` 可能由系统确认，不能标成用户人工接纳。详情保留原始字段及其来源；文档的接纳状态始终绑定选定修订。

**进度口径。** 顶部改为“当前有效通过 X / Y 步”，百分比只表示这一计数。Y 为当前运行定义的全部节点数，旧运行和自定义流程均按自己的定义计算。X 仅计入执行已结束、门禁通过且新鲜度有效的节点。节点要求人工接纳或属于 human 时，还需接纳已完成；其他节点不以 pending 接纳字段扣分。

没有运行或 Y 为 0 时显示“尚无步骤”，不绘制百分比。`aria-valuetext` 同时说明计数口径，并列出待接纳和过期数量。达到 100% 只表示当前定义的步骤满足上述条件；“已交付”独立读取工作项 `status=accepted`。结果过期会降低有效通过数，界面需说明回退原因。

**启动检查与本地阻塞分层。** readiness 分为 loading、ready、blocked、error；另列 `clientBlockers`。服务端 readiness 不知道未保存的浏览器草稿。需求草稿/冲突、章程读取错误、未选择模型目标等，应按动作需要合并到禁用原因中。

新派发要求 readiness 返回 ready、本地阻塞为空且相同资源无进行中的写入。readiness 返回 ready 但存在需求草稿时，显示“服务端条件满足，需求草稿尚未保存”。提供保存、处理冲突或工程设置入口，不显示可以直接运行。

本地需求草稿阻止新派发和“提交答复并继续澄清”，但不阻止查看材料、编辑或停止/核对原执行。文档草稿阻止对应文档版本接纳。草稿不能直接修改服务端门禁、新鲜度或接纳字段；保存后再采信服务端的失效结果。章程读取失败可能同时出现在快照和 readiness，显示时去重并保留来源。

下表只规定主动作及其文案，不替代四项事实的展示。

| 工程事实 | 建议文案 | 主要动作 |
| --- | --- | --- |
| readiness 尚未返回 | 正在检查运行条件 | 保留按钮位置，暂不派发 |
| readiness 请求失败 | 无法检查运行条件 | 重试检查 |
| readiness 返回阻塞 | 当前步骤还缺少条件 | 显示原因；跳到相应材料 |
| 服务端条件满足，但本地草稿未处理 | 需求尚未保存 / 草稿存在冲突 | 保存需求或处理冲突后重查 |
| 运行等待问题或授权 | 需要你处理 | 打开此工作项的待处理交互 |
| 正在执行 | 正在运行 · 已运行时长 | 查看运行；提供停止入口 |
| 执行结束，产物尚待处理 | 执行已结束 · 待审阅 | 阅读产物或查看复核结果 |
| 上游版本改变 | 结果已过期 | 查看变更依据，再创建新尝试 |
| 核对状态未确认 | 原执行状态待核对 | 核对原执行，按返回结果恢复 |
| 执行失败或已停止 | 执行失败 / 已确认停止 | 查看失败原因，核对后选择恢复或新尝试 |
| 流程已暂停或取消，且无活动执行 | 此流程暂不启动新步骤 | 查看流程状态；按实际条件恢复流程或创建新运行 |
| 工作项已接纳 | 此工作项已交付 | 查看证据；后续需求创建新的工作项 |
| 工程条件通过 | 已通过；需要接纳时另列接纳状态 | 查看证据或进入下一步骤 |

执行、门禁、新鲜度、接纳是四项独立事实。列表、任务区、检查器与运行详情使用同一展示模型。运行结束只说明执行终止，不能自动显示绿色“工程成功”。

**动作优先级。** 工作项已接纳时进入只读交付视图。其余情况先展示活动执行的待交互、待核对或运行状态，再处理失败恢复、过期结果与启动条件。readiness 只决定能否启动，不能盖住已有执行的处理入口。流程已暂停或输入已过期时，已有执行需同时显示该限制；回答和恢复仍由服务校验。

**待处理入口。** 需求澄清已在流程页展示；本轮补齐底座问题、表单和工具授权的跨页可见性，并聚合阻塞发现与可审阅产物。条目显示类型、所属步骤、尝试和相关版本，过期条目标明不可直接处理的原因。

数量为 1 时可直接进入对象；大于 1 时，头部入口打开完整待处理列表。任务条的单个主按钮只跳到最高优先项，并提示还有多少项。列表中保留准确的 session、interaction、finding 或 artifact revision 定位。

澄清按 session、底座请求按 interaction、发现按 finding、产物审阅按当前 revision 去重。readiness 原因和 node.blockers 是条件说明，不能因文案重复另算一个待办。跨工作项全局中心留待摘要 API 支持。

**运行详情保留现有能力，再追加结构化复核。** P1 把相关详情移到任务旁，运行记录页继续提供完整历史。以下项目作为保留清单逐项验收。

| 现有能力 | 新布局要求 |
| --- | --- |
| 输入/输出 Token、实际费用、模型目标和状态 | 保留 sandbox 不调用 API、费用未知等真实文案 |
| 执行身份与恢复绑定 | 保留初始和恢复的 session / turn / run 身份链 |
| 冻结需求、章程与澄清历史 | 保留需求版本与哈希、章程全文、完整澄清记录 |
| 固定输入、提示词、错误与最终输出 | 摘要可折叠，完整原始材料仍可打开 |
| 停止、核对、恢复 | 保留原执行身份与控制语义 |
| 底座问题、表单和一次性授权 | 保留全部字段、答复和允许一次 / 拒绝行为 |

追加覆盖检查、反例检查、结论、证据与未解决问题卡片，原始 JSON 放入折叠区。当前流程上的“启用含澄清的新流程”入口继续保留，沿用适用条件；升级创建新运行，历史运行不被覆盖。

首版只呈现已记录的活动。Maka 适配器当前每秒查询状态，没有提供逐 Token 或工具起止事件。细粒度时间线需先扩展执行事件契约；没有数据时不能绘制虚构工具调用或百分比。

**控制语义。** “停止本次执行”先显示请求处理中，收到终态后再确认停止。失败和未知状态进入核对流程。现有流程暂停只阻止后续节点启动，不能表示当前执行已暂停。验证任务没有公开取消 API，界面不展示可用的取消验证动作。

**同步语义。** 分开显示事件连接、最后成功同步和 Maka Host 可用性。P0 补 `onopen/onerror`、重连反馈与手动刷新。空闲无事件属于正常状态，不能仅按沉默时长判定离线。

现有 `/api/events` 已接受 `after`，输出 SSE 的 `id: seq`，每批最多返回 200 条。客户端当前不传 after；服务端未读取重连时的 `Last-Event-ID`。P2 补齐这套游标恢复，并为事件增加 workItemId、必要时增加 projectId。原有 seq、entityId、kind 和事件内容继续兼容。

同一连接重连时，合法的 Last-Event-ID 优先于初始 after，避免退回旧起点。没有该请求头时使用合法 after；两者都没有才从初始位置读取。拒绝非法或负数游标；客户端按 seq 去重，并按批补齐断线期间超过 200 条的事件。

EventSource 自动携带的最后接收 ID 不能代表业务快照已同步。客户端保留尚未完成的失效刷新，成功处理后再推进应用层游标。断线重连也不能丢弃仍未成功刷新的范围。

游标因数据重建或保留期变化而无法恢复时，服务显式返回重新同步指示，客户端重取当前快照。恢复期间合并失效刷新，避免每条旧事件都触发全量请求。旧版无作用域事件继续保守刷新，不能被静默忽略。

**提交与输入。** 问答、需求和评论默认 Enter 换行；适合的提交区可支持 Ctrl/Cmd+Enter。所有快捷提交均检查中文 IME 合成态。真实授权维持“允许一次 / 拒绝”，不新增缺少底座支持的“始终允许”。

## E 如何降低产物审阅成本

**需求输入。** 保留上传、粘贴和仓库导入。将附件显示为紧凑条目，按需编辑正文；明确区分“已加入草稿”和“已保存并供 AI 使用”。保存后显示新的需求版本与受影响步骤，失败时保留草稿。

**澄清。** 在当前任务主体展示问题、选项、自由答复和答复保存状态。复用现有 400ms 草稿保存与版本冲突行为。提交后给出“正在写回规格 → 已产生新版本 → 查看变化”的连续入口。

**文档。** 继续以人类简报为默认视图。顶栏放产物、修订、当前/历史、接纳状态与阅读方式。完整 AI 执行文档增加 Markdown 预览与目录，编辑仍保留明确的保存新版本动作。首次可沿用 textarea，避免同时更换编辑器。

**比较。** 用实际行级或段落差异替换两列全文。默认比较“已接纳版本 → 选定候选”，冲突时比较“服务器版本 → 本地草稿”。没有接纳版本时展示首次新增，不能伪造基线。长段落支持定位下一处变更，显示双方修订与哈希。

**评论。** 首版保留现有文本锚点，支持在对应原文中查找。匹配不唯一时说明需要选择，不能跳到错误段落。稳定段落 ID、偏移和跨版本迁移需要扩展评论契约，后续再做。

**接纳。** 操作区解释当前版本、草稿、澄清、复核和过期条件。简报保留来源修订、内容哈希与摘录标识。用户通过简报进入审阅，服务端仍基于完整执行文档和真实证据判定接纳。

**代码。** 先将现有 patch 解析为文件列表与 hunk，默认统一视图；空间充足时再支持分屏。行号使用 hunk 的旧/新源码行号，文件头不计入增删。覆盖重命名、删除、二进制、无末尾换行和空差异。

当前界面 diff API 调用 `workspaces.diff()`，对未跟踪文件只返回名称。另一条 `reviewDiff()` 已为复核提示补入未跟踪文本或二进制 SHA-256，但它属于模型复核材料路径。单文件超过 512 KiB、总材料超过 1 MiB 会抛错，并排除工具与工程内部目录。界面不能直接改接这个函数。

P2 新增面向用户审阅的只读结构化差异接口。返回候选与基线哈希、文件状态、大小、二进制标识、可用的正文/补丁，以及截断标记和原因。大文件按文件或分块读取，显示已返回与总量；已有排除规则和路径边界继续生效。

完整新文件内容未提供前，明确显示“内容尚未提供”。截断展示不能作为完整复核证据，不能改变模型材料上限或放宽接纳门禁。二进制显示大小与哈希，并说明正文未作语义核验。

代码接纳条件较复杂。第一版可汇总已知证据并进入现有接纳步骤，最终仍由服务校验。P2 新增只读预检接口，只提取 `acceptCode()` 中可共享的无副作用断言。

预检不调用 `acceptCode()`，不做 checkpoint、cherry-pick、commit，也不产生接纳记录。现有入口中的章程刷新和外部改动扫描会更新状态，不能把前半段原样当只读接口。需要的版本与指纹通过读取和计算取得，发现变化就返回待重新同步说明。

预检展示“截至检查时刻”的结果，不能用它直接放行。真正接纳仍在互斥保护下重新校验输入版本、候选树哈希、来源、测试与复核证据、源仓库基线等条件。预检后发生变化必须重新拒绝或要求核对，不能沿用旧绿灯。

Markdown 渲染按普通文档处理：默认禁用原始 HTML，不执行脚本；链接和导出沿用桌面限制。不为这轮阅读改进引入 iframe 工件执行环境。

## F 视觉与组件应如何收敛

视觉方向采用安静、精确的工程工作台。用暖灰和墨绿保持现有识别，边框和留白解释层级；将颜色主要留给动作和状态。减少每个区域都有独立卡片的碎片感。

下表是建议起点，实施时需测量对比度，并验证不同屏幕下的阅读效果。

| 语义 token | 建议值 | 用途 |
| --- | --- | --- |
| `--surface-canvas` | `#F5F6F2` | 应用画布，沿用现有暖灰 |
| `--surface-navigation` | `#EDF0E9` | 全局导航 |
| `--surface-content` | `#FFFFFF` | 正文与主要工作区 |
| `--surface-raised` | `#FFFEFA` | 浮层，配合柔和阴影 |
| `--text-primary` / `--text-secondary` | `#243C38` / `#596D5E` | 主要与辅助正文 |
| `--accent` | `#0B4940` | 主操作、选中与焦点体系 |
| `--success` / `--warning` / `--danger` | `#27664E` / `#80530D` / `#A43D35` | 通过、待处理、失败；配文本和图标 |
| `--border-default` / `--border-control` | `#E2E6DF` / `#718579` | 装饰分隔 / 交互控件边界 |

`--border-control` 从审计中的 `#84968C` 加深为 `#718579`。在白色、画布、导航和浮层上，对比度分别约为 3.94、3.63、3.42、3.90:1，均达到 3:1。浅色 `--border-default` 只用于装饰分隔，不作为唯一控件边界。通过色与品牌色接近，所有状态始终配文字和图标。

**排版。** 界面正文建议 14px/1.6，长文 15px/1.8，辅助信息 12px。正文与辅助文字都需达到 4.5:1；交互边界与焦点需达到 3:1。11px 仅用于非关键元信息。

保留本机中文 UI 字体和等宽代码字体，简报标题可延续衬线字体。无需引入商用字体或远程字体依赖。

**尺寸。** 使用 4px 间距基准，常用 8/12/16/24/32。按钮至少 36px 高，触屏主操作建议 44px。按钮圆角 6px、内容区 10px、弹窗 14px；单一容器避免双重闭合边框。

**动效。** hover 和焦点变化约 120ms，折叠展开约 180ms，抽屉约 220ms。先用 CSS 和原生 disclosure；拖拽时不做滞后动画。尊重 `prefers-reduced-motion`，状态只在必要区域提示。稳定条目 key，刷新不重复播放整页入场动画。

**分栏。** 使用 Pointer Capture、拖动死区、宽度钳制和 Escape 撤销。分割条提供 separator 语义与方向键调整，处理 pointercancel 和 lostpointercapture。双击恢复默认宽度，折叠后保留恢复入口。首版没有交互式 iframe，无需复杂遮罩引擎。

建议先提取 `Button`、`IconButton`、`StatusBadge`、`InlineFeedback`、`Disclosure`、`Dialog`、`Drawer` 和 `ResizablePane`。沿用现有 React 19、Lucide 和 CSS；本轮不要求迁移 Tailwind、Framer Motion 或全局状态框架。暗色主题列入后续项，不能仅增加反色变量后就宣告完成。

## G 如何分批落地与划定接口边界

下表记录方案的分批实施顺序，每批可独立评审。实际文件和完成情况见实施与验收记录。

```timeline
P0 | 操作可解释 | readiness 错误恢复、统一状态、待处理入口、同步提示
P1 | 工作台与审阅 | 紧凑布局、当前任务、就地运行详情、复核报告、文档真实比较
P2 | 数据正确性与规模 | 接纳预检、完整代码差异、SSE 恢复、按需读取和分页
P3 | 后续能力 | 有真实事件后再做逐 Token 输出和工具时间线
```

| 批次 | 主要改动入口 | 完成条件 |
| --- | --- | --- |
| P0 | `Flow.tsx`、`App.tsx`、`context.tsx`；四项事实、主动作、进度、本地阻塞与反馈组件 | 本地草稿不能被 ready 覆盖；待处理多项可列表查看；启动失败不盲目重发 |
| P1 | `App.tsx`、`Flow.tsx`、`Runs.tsx`、`ClarificationPanel.tsx`、`Documents.tsx`、`styles.css`；位置恢复与分域 pending | 1000×700 主动作保持可见；布局不来回切换；原运行能力与升级入口全部保留 |
| P2 | `app.ts`、`service.ts`、`workspaces.ts`、`api.ts`、`CodeView.tsx`；数据 hook 与操作身份复用 | 差异接口明确完整性；预检无副作用；接纳时重新校验；SSE 游标和作用域恢复正确 |
| P3 | 现有 Maka 适配器与执行事件契约，再接入运行面板 | 逐条事件来源、顺序、去重和恢复均可验证 |

P0 开始时提取最少量语义 token 和基础组件。P1 调布局时逐块迁移旧样式，移除对应重复覆盖；每批保持可运行。不要先全量改样式再处理工程交互。

| 能力 | 当前可以做 | 需要新增或扩展 |
| --- | --- | --- |
| 当前任务、待处理、报告卡片 | 使用现有快照、澄清面板、底座请求与双视角 reviewReport | 跨项总览另需摘要接口；本地阻塞由客户端单列 |
| 文档真实 diff、Markdown 预览 | 快照已有修订全文，可先在前端实现 | 稳定跨版本评论锚点需契约扩展 |
| 代码文件与 hunk 浏览 | 解析已有 patch；reviewDiff 已有模型复核材料 | 单独扩展用户审阅接口，返回正文、二进制与截断元信息 |
| 接纳条件解释 | 展示现有证据与已知阻塞 | 提取纯校验用于预检；正式接纳重新检查，预检不放行 |
| SSE 状态反馈 | 已有 after、SSE id 和 EventSource | 补 Last-Event-ID 恢复与作用域，覆盖大于 200 条的断线积压 |
| 运行历史筛选 | 现有快照可做本地筛选 | 真正降低传输需摘要列表、分页和详情接口 |
| 流式正文与工具时间线 | 当前只显示已确认状态及最终输出 | 需 Token delta、工具事件与持久恢复契约 |

**状态组织。** 从 `App.tsx` 提取工作空间选择、快照请求、事件连接和操作状态。P1 用查询参数保存 `{project,item,view,node,artifact,revision,attempt}`，并持久保存跟随/固定查看模式。沿用现有桌面静态入口，不另引入一套路由路径。

URL 只保存对象定位，正文和凭据不进入 URL。切页、刷新和浏览器后退恢复对应对象；切换工作项时记录并恢复各自位置。失效定位回退到有效对象，并显示原因。保留现有 SSE 刷新不清除手动选择的行为。

**操作锁。** 将 busy 按需求保存、评论提交、产物变更和运行控制划分；同一版本资源的互斥仍共用锁。保留预期版本校验与原执行身份核对。写请求遇到网络不确定性时先核对结果；不能用新幂等键自动重发并产生第二次尝试。

**刷新。** 首先合并请求，保留现有过期请求保护。现有事件不包含完整工作项作用域，暂时对无法判断归属的事件保守刷新；补齐作用域后再过滤。快照会带全部历史正文，前端分页只减少渲染，不能声称减少传输。

**执行底座。** 当前继续使用 Maka。遵守官方 Apache Maka 0.2.0 正式源码发布、校验和、签名指纹与生产依赖打包政策。此方案不恢复独立 harness 选择、注册表或额外适配器建设。

## H 怎样验收并交给复核

下表保留设计中的验收要求，实际结果以实施与验收记录为准。

| 代表性场景 | 应观察到的结果 |
| --- | --- |
| 首次打开一个工作项 | 首屏可识别当前任务、下一动作和主要阻塞；四项事实可独立读取 |
| readiness 请求失败后恢复 | 明确错误和重试入口，恢复后能正常派发 |
| readiness 返回 ready，但需求有草稿或冲突 | 客户端仍阻止新派发，显示保存/处理入口；原执行可查看、停止与核对 |
| 运行结束但门禁阻塞、结果过期或待人工接纳 | 四项事实分别显示，有效通过计数不虚增，交付状态不被百分比替代 |
| 无需人工接纳的节点 acceptance 仍为 pending | 显示无需人工接纳，按执行、门禁与新鲜度计入有效通过 |
| 澄清答复 → 修订规格 → 复核 → 接纳 | 保留问题与答复版本，可定位修订变化和依据 |
| 运行等待交互时切换页签 | 待处理计数保留；可回到准确的原请求 |
| 当前工作项同时有多个待处理项 | 头部打开去重列表，主动作进入最高优先项，各项步骤与版本可定位 |
| 更新需求或章程 | 标出过期结果；旧运行仍显示其冻结输入 |
| 停止回执丢失、断线重连、恢复执行 | 核对原身份；不重复派发，不提前宣告停止 |
| SSE 断线期间积压超过 200 条事件 | 初始 after 与重连 Last-Event-ID 均可恢复；按 seq 补齐去重，不重放全部历史 |
| 新旧两种作用域事件混合 | 新事件只失效相关工作项；旧无范围事件仍保守刷新 |
| 文档冲突、历史版本、简报来源不匹配 | 草稿保留，历史只读，来源不符时阻止混用 |
| 候选变更后旧测试或复核失效 | 解释失效原因，服务端拒绝错误接纳 |
| 新文件、重命名、二进制及大补丁 | 文本可读；二进制有类型/大小/哈希；超限明确截断边界和原因；文件头不计增删 |
| 重复调用接纳预检 | 无 checkpoint、cherry-pick、commit 和接纳记录，不刷新写入工程状态 |
| 预检后更改候选、输入、命令或源仓库基线 | 正式接纳重新校验，拒绝不一致；不能沿用预检结果放行 |
| 保存评论或草稿时发生后台刷新 | 输入、选择与阅读位置保持稳定 |
| 固定历史步骤后切项、刷新与后退 | 固定对象恢复；显式回到当前任务后才恢复跟随 |
| P1 前后对照运行页与旧模板 | Token/费用、身份链、冻结材料、完整输出、交互控制和升级入口逐项保留 |

**布局与可访问性。** 覆盖桌面 1440×940、1280×800、1000×700，以及 Web 800px 和 390px 宽度。页面无横向溢出；代码和差异允许局部滚动。完成 Tab、Shift+Tab、方向键、Escape、焦点恢复、分割条键盘调整和中文输入法检查。缩放到 200% 时仍可到达主动作。

在 1000×700 下滚动长问答、复核与文档，主动作仍须保持可见。连续跨断点调整宽度，确认先收上下文再收导航，稳定宽度下不反复切换。控件边界需在白色、画布、导航与浮层上逐一达到 3:1，焦点环与状态文字另行检查。

**性能样本。** 使用确定性夹具覆盖 200 次尝试、50 个文件、1 万行 patch 和长文修订。先记录基线，再决定虚拟化或 Worker。常规刷新不重新解析未变更文档；用户查阅历史时不自动拉到底部。数据接口分页与前端渲染优化分别验收。

**工程检查。** 实施代码后执行 `npm run typecheck`、`npm test`、`npm run build`，并运行相关桌面 smoke。为状态组合、差异解析、请求失败恢复及原执行身份增加必要回归；使用隔离数据目录，不调用真实供应商完成界面验收。打包行为有改动时再运行打包版 smoke。

**Claude Code 复核入口。** 检查状态展示是否偷换工程通过语义，预检是否与服务共享。检查 SSE 恢复与操作锁的版本互斥。检查新布局是否损害已有草稿和焦点行为。参考组件的模拟状态不得进入生产逻辑。
