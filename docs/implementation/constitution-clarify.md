项目章程通过仓库根目录的 AGENT.md 或 AGENTS.md 管理。
需求澄清现在是独立步骤，位于需求规格与规格复核之间。
默认流程增加为 13 步。

## A 怎样管理项目章程

打开“工程设置”，找到“项目章程”。
选择 AGENT.md 或 AGENTS.md，编辑并保存正文。
应用将文件写入注册项目的仓库根目录。
已有文件会自动读取；两个文件都存在时，都会进入上下文。

章程优先于补充工程规则。
每次尝试保存章程全文和内容哈希。
在“运行记录”可以查看此次使用的章程。
源文件修改会使旧结果过期，下一次尝试读取当前文件。
文件需使用 UTF-8 编码，每份最多 128 KiB。

保存章程属于 Git 工作目录的修改。
新建工作项前，按项目习惯提交章程文件。
文件读取失败时，应用显示原因并阻止运行。

## B 澄清步骤怎样工作

```flow TB
需求正文与文档 -> 需求规格: 生成候选规格
需求规格 -> 澄清分析: 检查设计和验收的关键未知信息
澄清分析 -> {还需要确认吗}
{还需要确认吗} -> 结构化问题: 需要
结构化问题 -> 用户答复: 整个会话最多 5 个问题
用户答复 -> 澄清分析: 保存并继续分析
{还需要确认吗} -> 修订规格: 信息足够
修订规格 -> 规格复核: 保存问答记录
规格复核 -> 工程设计: 人工接纳规格
```

点击“需求澄清”，运行该步骤。
有问题时，选择建议答复或输入自己的决定。
点击“提交答复并继续澄清”。
信息足够时，模型返回完整的修订规格。
应用将问答记录追加到规格，创建新版本。

模型已经有足够信息时，可以直接完成澄清。
未答复问题或未决标记会阻止完成。
没有完成澄清的规格无法进入复核、接纳或设计。

## C 变更和重启怎样处理

| 情况 | 处理 |
| --- | --- |
| 刷新问答页面 | 保留本地与数据库中的答复草稿 |
| 重启桌面程序 | 恢复问题、已保存的草稿与已提交答复，不重复派发旧尝试 |
| 需求、规格或章程修改 | 旧问答失效，基于新的依据重新澄清 |
| 旧问答失效 | 保留历史问题、已提交答复和当前窗口的草稿查看入口 |
| 手动点击重新分析 | 保留旧问答历史，建立新的澄清会话 |
| 未开始的默认工作项 | 自动补上独立澄清步骤 |
| 已开始的旧运行 | 保留旧定义，可从流程页启用新的运行 |

答复草稿会自动保存到工程数据库。
界面显示保存状态，保存完成后可关闭窗口。
保存草稿不会调用模型，提交答复后才继续分析。
