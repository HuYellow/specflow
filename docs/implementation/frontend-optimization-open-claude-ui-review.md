方案可以按这个方向做。它把参考项目固定在 [open-claude-ui · 2834bc1](https://github.com/Caho1/open-claude-ui/tree/2834bc158a4849f21c97cbb2e0b10525f6e646f1)，只借表面、阅读节奏和局部交互，并明确不搬入 Tailwind、Framer Motion、模拟授权、虚构流式输出和 iframe 沙箱。实施前需要先改几处与仓库不符的判断，并补上状态模型和最小窗口布局的决定。

审阅对象是 [前端优化方案](frontend-optimization-open-claude-ui.md)。对照范围是 2026-10-15 的 SpecFlow 工作树，以及上述固定提交中的示例源码。

## A 哪些判断已经对上

默认流程的 13 步与 `templates/spec-driven/workflow.yaml` 一致，五组映射也正确。自定义流程保留定义顺序、旧运行不补造澄清节点，这两条都该保留。

当前问题里，这些定位是准的。

| 方案判断 | 工作树证据 |
| --- | --- |
| readiness 失败后按钮只是禁用 | `Flow.tsx` 用 `.catch(() => undefined)` 吞掉错误；请求未返回时 `readiness` 被清成 `undefined` |
| 列表和检查器表达的不是同一件事 | 列表用门禁和新鲜度；检查器只显示 `labels[execution]`。`completed` 在列表里是「待接纳」，在检查器里是「执行已结束」 |
| 文档比较和代码审阅成本高 | `Documents.tsx` 比较视图是两列全文。`CodeView.tsx` 按补丁原文逐行渲染，行号是显示序号 |
| 未跟踪文件在界面差异里只有名称 | `workspaces.diff()` 只拼接未跟踪文件名 |
| 不能画逐 Token 时间线 | `MakaAdapter.observe()` 每秒 `turn.query` 一次，没有逐 Token 或工具起止事件 |
| 暂停和停止是两件事 | 暂停只进入 readiness 的「流程已暂停或结束」，不调用 `turn.stop` |
| 验证不能显示取消 | 验证的 HTTP 入口没有取消接口 |
| 授权保持一次性和拒绝 | 现有交互卡只有「允许一次 / 拒绝」 |
| 最小窗口要单独设计 | `apps/desktop/main.ts` 的最小窗口是 1000×700 |
| 快捷提交需要输入法守卫 | 前端没有 `isComposing` 检查。澄清草稿确实按 400ms 写回 |

参考示例里，这些边界也判断对了。

## B 需要改正的引用

**分栏示例已经有取消，缺的是键盘和指针收尾。** `ArtifactsSplitPaneResizer.tsx` 有 `role="separator"`、Escape 回滚和双击归位。移动处理里没有注释所说的 4px 死区，也没有方向键、`pointercancel` 和 `lostpointercapture`。拖拽遮罩写的是 `pointer-events: none`，挡不住 iframe 抢指针。方案里的重写要求仍然对，应把「缺少取消处理」改成「已有 Escape，缺少方向键和指针取消」。

**差异示例会把文件头当成内容行。** `parseGitDiff()` 看到以 `+` 开头就计为新增，`+++`、`---` 和 `diff --git` 都会错。方案要求「文件头不计入增删、使用 hunk 源码行号」应保留，同时写明不能直接移植这个解析函数。

**未跟踪文件的正文已经存在于另一条服务端路径。** `reviewDiff()` 会把未跟踪文本和二进制哈希塞进复核提示，单文件超过 512KB 或总补丁超过 1MB 时直接抛错。界面不能改接这个函数。P2 需要的是带截断元信息的审阅接口。

**事件游标已经有一半。** `/api/events` 接受 `after`，并写出 SSE 的 `id`。它不读 EventSource 重连时自动带上的 `Last-Event-ID`。客户端现在打开的是不带游标的 `/api/events`。事件只有 `seq`、`entityId`、`kind`，没有工作项范围，每次最多返回 200 条。P2 应接上这个响应头，并补作用域，而不是从零设计游标。

**待处理交互并不都在运行页。** 需求澄清已经在流程页的 `ClarificationPanel` 里。真正缺的是工具授权、底座提问和表单。它们只挂在运行页当前选中的那一次尝试上，其他页签看不到。

**readiness 看不见本地草稿。** 未保存的需求、章程读取失败，现在都在客户端额外禁用按钮。服务端 readiness 只认识已保存内容。展示模型必须单列这类客户端阻塞，否则 P0 会把「可以运行」显示在仍有草稿的时候。

## C 实施前要补的决定

**四项事实和主动作分开画。** 现在的文案表容易被实现成一枚新徽章，等于把今天的 `status()` 换个名字。列表、任务区和运行详情应固定显示执行、门禁、新鲜度、接纳。主动作只决定一个按钮。顶部进度「N / Y 步骤通过」和百分比也要按这四项重定义，否则它仍会像工程完成度。

**多个待处理项进列表。** 头部已经有数量。数量大于 1 时，点击应打开去重后的列表，每项带步骤和版本。单个按钮只能跳到优先级最高的一项。

**1000×700 要把主动作钉住。** 最小窗口高度 700。紧凑头部、页签、分组条和任务区叠起来后，主按钮会掉到首屏下面。当前任务条需要在这个尺寸下保持可见。断点也要规定固定顺序：先收上下文，再把导航收成 64px。现在的两条规则都看「主体剩余宽度」，一边收起会让另一边重新出现。参考手册第六篇的容器查询适合工作主体内部压缩。窗口宽度只做初始档。当前导航实际是 236px，方案写的 224px 要一并说明。

**刷新已经不会清空选择。** `selectedNode` 为空时，派生逻辑会跟着活动步骤变。用户点过步骤后，SSE 刷新不会改选择。方案要区分「跟随当前任务」和「钉住用户选择」。切工作项仍会清空位置。URL 只放对象定位这一点是对的。打包后的非 API 路径会回退到 `index.html`，用查询参数比再引入一套前端路由稳妥。

**运行详情的第一版清单要写成追加。** 现在的运行页已有 Token、费用、执行身份、冻结需求、章程和澄清历史，以及停止、核对、恢复。若「第一版展示」被当成完整清单，这些会在 P1 丢掉。旧模板上的「启用含澄清的新流程」也要留在新工作台里。

**接纳预检只能解释，不能放行。** `acceptCode()` 前半段是断言，后半段会做检查点、拣选和提交。可复用的是断言函数。预检结果到真正接纳之间仍可能变化，界面文案要保持为说明。

## D 配色

正文色达到 4.5:1。控件边界有两处达不到方案自己写的 3:1。

| 组合 | 对比度 | 结论 |
| --- | --- | --- |
| `#243C38` 在 `#F5F6F2` 上 | 10.9:1 | 正文通过 |
| `#596D5E` 在 `#FFFFFF` / `#F5F6F2` / `#EDF0E9` 上 | 5.6:1 / 5.1:1 / 4.8:1 | 辅助正文通过 |
| 白字在 `#0B4940`、`#27664E`、`#80530D`、`#A43D35` 上 | 均高于 6:1 | 按钮和状态文字通过 |
| `#84968C` 在 `#FFFFFF` 上 | 3.1:1 | 控件边界刚过 3:1 |
| `#84968C` 在 `#F5F6F2` / `#EDF0E9` 上 | 2.9:1 / 2.7:1 | 画布和导航上的控件边界不足 |

通过色 `#27664E` 和品牌色 `#0B4940` 都是深墨绿。状态必须同时有文字和图标。

## E 建议的修订顺序

1. 改正分栏、差异解析、SSE 游标、`reviewDiff()`、待处理交互和本地草稿这六处引用。
2. 把执行、门禁、新鲜度、接纳写成独立事实，主动作和进度条都从这四项派生。
3. 规定断点收起顺序，并要求 1000×700 下主动作保持可见。
4. 把运行详情和旧流程升级入口写成保留项。
5. 加深 `#84968C`，使它在画布和导航上都达到 3:1。
